# M6 Shadow 会话收据验证合同（授权前 R0）

当前状态：仅有离线验证器与合成签名测试。无生产授权、受信任密钥、实时见证服务、真实会话或真实事件。`action=no_order`；用户作最终投资决定。

## 三层证据

1. 用户授权收据：独立授权密钥签名，绑定 `SHADOW`、交易所、有效窗口、部署/配置 Hash、完整授权范围清单 Hash 与运行公钥。证据包必须同时提供 scope manifest、deployment manifest 和 runtime config 的实际字节；验证器逐字节重算 Hash，并核对 scope 中的授权 ID、模式、交易所、有效期及部署/配置交叉绑定。验证者还必须从仓库/WPS/证据包之外取得授权公钥和**被批准收据的精确 SHA-256**；仅能验证签名或随包附带公钥不算授权。
2. 每会话运行收据：授权绑定的运行公钥签名，含交易所、官方会话日期/来源 Hash、运行 ID、开始与完成时间、资源检查、制品 Hash、前序收据 Hash。失败会话也保留在链上，但不计入成功连续段。
3. 独立见证收据：另一把受信任公钥签名，绑定运行收据 Hash、严格递增序号、前序见证 Hash 与接收时间；接收须在完成后 15 分钟内。授权、运行、见证公钥不得相同。
4. 独立接收链：第四把受信任公钥签名原始会话收据字节 Hash、服务端接收时间、单调序号、密钥纪元、部署 Hash 和前序记录 Hash；链头的精确 Hash、序号和钉住时间必须由证据包外提供。会话字节没有进入该链，或链头/纪元/部署不匹配时，连签名候选会话也不得形成。四把公钥必须互异。
5. 运营准入收据：第五把独立公钥在 intake 链头形成后签名，并由包外钉住精确收据 Hash；它绑定授权、scope、部署、配置、intake 链头、交易所、有效期、20 会话/1 事件门槛和重置政策。它是对已接收观察结果的计数准入，不是启动生产 Shadow 的授权。只有 `m6_shadow_admission.verify_operational_shadow_bundle` 的结果可进入运营会话计数；普通候选验证永远不能晋级。

验证器位于 `src/value_investment_agent/m6_shadow_receipts.py`，字节合同位于
`m6_authorization_artifacts.py`，独立接收链合同位于 `m6_independent_intake.py`。它们只消费证据，不签发授权、启动调度或连接生产；当前 CLI 不接受任意密钥参数。当前签名验证结果只列为 `signed_candidate_sessions`，**绝不增加**已验真实会话：只有未来由生产范围外真正受控的 intake 身份和链头才能提供运营证明；本地合成的信任根、签名与钉住时间仍可事后制造。合成测试即使通过也不能充当真实 Shadow。

运营准入合同位于 `m6_shadow_admission.py`。合成 admission 可以证明代码只有在完整五方绑定后才计算会话，但不能证明真实用户授权、真实部署或自然交易日已经发生。真实事件还必须通过事件原件与运行制品联合验证，不能由会话 admission 自动记分。

## 上线前仍须独立证明

- R3：逐项批准的生产范围、密钥保管与轮换、真实部署/数据库/调度/通知/回退和独立见证入口；把信任根固定在受控配置中，不能从待验证 bundle 自取。
- R6：授权后的真实交易所会话逐日形成、独立接收时间锚、无缺失/重大故障的连续不少于 20 会话。签名里的自报时间不能单独证明真实发生；后补收据不计数。
- 真实财务或资本配置事件须另以一手原件、材料性复核及运行观察绑定；当前事件计数仍为 0，不能凭运行收据中的一个 Hash 自动给事件记分。
- 任何停机、关键故障、签名密钥失控或部署 Hash 变化均依授权规则停算并重新判定受影响观察窗口。

该合同是未来会话验收的工程前提，不是生产授权请求，也不改变 `M6_OPERATIONAL=NOT_STARTED` 或 `INITIAL_ASSISTED_USE=NOT_REACHED`。

## 真实事件运营见证：离线候选合同

当前 600519 SSE 索引覆盖校验拒绝 `category`、`searchkey` 等限制性查询，要求已发现的完整证券 ID、完整扫描窗口和选中公告在窗口内。它仅核对归档索引自身和包外 Hash，不证明查询当时确由 CNINFO 完整返回。

`m6_event_observation.verify_event_observation_candidate` 校验传入的归档 PDF 字节、CNINFO 索引行、规范化材料性复核、内部自洽的 ACTUAL M5 收据、同一授权 Shadow 会话的签名链，以及该会话 `artifact_sha256` 对应的事件观察制品字节。索引的独立输入 Hash 须同时匹配 review 的 `scan_sha256` 与 evidence ref；证券、公告 ID/标题、毫秒时间戳、PDF URL 与来源字节 Hash 逐项核对。交易所会话由归档官方日历原文推导，不能手填并省略中间交易日。M5 review/receipt、索引及日历原文的期望 SHA-256 与允许来源主机须从观察包外传入；验证器本身仍不能证明这些输入由独立机构钉住或是实时重新取得。观察制品固定 `event_id`、`source_event_id`、决定 ID、来源 URL/Hash、M5 收据文件及状态 Hash、M6 授权 Hash、运行 ID、交易日和观察时间；跨运行/授权重放、上一交易会话之前的旧事件、原件替换、ID/Hash 冲突和时间倒置均失败关闭。

成功结果也只包含 `offline_candidate_valid=true`、`operational_event_proven=false`、`verified_real_event_count=0`。本地传入的信任根与签名者声称的 `received_at` 可事后制造，不能证明真实生产实例或不可补写的实时接收。后续若要给 M6 真实事件记 1，必须额外独立钉住生产授权/部署身份及密钥纪元、M5 制品索引及公告来源记录，并由与运行方隔离的 append-only intake 在到达时写入原始收据字节 Hash、服务端时间和单调序号；验证其不可回填、授权窗口、实际运行制品和事件到达时限。公开 CI 使用的是可移植的合成 lineage 测试；真实 M5/Shadow 联合测试仅在本机归档原件存在时运行，不能由 CI 的合成通过冒充。历史 600519 M5 回放及合成签名测试均不得作为运营证据。

`m6_event_admission.verify_operational_event_observation` 组合验证上述候选、五方运营会话准入与一份由第五方 admission 密钥另行签署且包外钉住 Hash 的事件准入收据。收据逐项绑定事件候选、公告/索引/观察制品 Hash、会话收据、生产授权、运营 admission 与 intake 链头。只有这个组合结果能够进入 `real_events`；账本中的布尔声明、普通候选、历史回放或仅有运营会话均继续计 0。
