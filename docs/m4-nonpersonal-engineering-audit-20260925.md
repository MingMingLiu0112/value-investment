# M4 非个人化工程审计：2026-09-25

本审计只判断可在没有真实 IPS、资产、现金、持仓、成本或风险偏好的情况下验证的工程。
它不批准个人化仓位、买卖复核、真实账户导入或 M4 产品验收。

## 审计结果

`M4 non-personalized engineering = COMPLETE`。

`M4 personalized acceptance = PENDING_USER_PRIVATE_INPUT`。

这两个状态必须同时存在。前者表示系统不会因为缺私人资料而停在模拟原型；后者表示系统
仍不能对任何真实账户给出个人化风险、容量或股息结论。

| 能力 | 真实代码证据 | 失败关闭证据 |
| --- | --- | --- |
| IPS/快照合同 | `portfolio_contracts.py` | 缺失、模拟命名空间、未对账和未确认数量阻断 guidance |
| 私有输入边界 | `private_portfolio_intake.py` | AES-256-GCM、密钥/仓库/WPS 隔离、篡改/错误密钥/覆盖拒绝 |
| 私有对账 | `portfolio_reconciliation.py` | 现金、证券、交易所、数量、公司行为差异；一致也需人工确认 |
| 集中度与流动性 | `portfolio_risk.py` | 单股、行业、周期、现金与未知风险属性分别报告 |
| 容量与仓位复核 | `position_guidance.py` | 共享预算守恒、全现金、集中/分散反例、正向 M3 binding 缺失阻断 |
| 股息现金流 | `dividend_income_projection.py` | 当前、forward、normalized 分开；缺快照/适用性保持不完整 |
| 事件联动 | `m4_m5_integration.py` | 事件失效只能暂停/否定受影响制品，不能产生订单 |
| 展示候选 | M4/M5 与 M7 候选构建器 | 仅只读模拟展示，不替代真实组合或正式发布 |

本轮复跑 `74 passed`，覆盖私有输入、对账、合同、风险、仓位、股息、M4/M5 集成与加密
备份边界。测试通过证明合同和反例，不证明投资方法有效或个人组合已经对账。

## 尚未完成且不可由工程伪造的输入

- 用户确认的 IPS：账户范围、可投资资产、最低/紧急现金、期限、集中度上限、风险偏好和
  股息目标；
- 同账户、同日期的实际持仓/现金快照及对账证据；
- 用户对对账差异和最终 `RECONCILED` 状态的人工确认；
- 与已通过 M3/M5/M6 门相结合后的个人化验收。

私有输入必须保持在 WPS 与仓库之外，密钥也必须独立保存。即使完整输入到位，系统输出
仍只能是带理由的人工复核，不会下单。
