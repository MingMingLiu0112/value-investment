# 证据分层存储

## 目标

服务器只承担 PostgreSQL、定时采集、当前研究案例、近期运行证据和 Excel
导出。历史财报 PDF 的冷归档保存在本机：
`D:/GPTProject/value-investment/evidence-archive/`。

服务器不是唯一证据副本。本机冷归档也不是服务器可直接读取的运行目录；已
归档原件不能被服务器解析任务自动重新使用，除非先恢复一份已核验副本。

## 服务器保留范围

- 当前首例及下一批深度研究标的：600519、000333、601088。
- 当前重点候选的最近两份法定财报，以及尚在解析或复核队列中的文件。
- 最近 90 天的行情、交易日历、费用、公司行动和运行回执。
- 数据库备份、配置清单和用于恢复当前任务的最小证据集。

其余已解析、未处于任务队列且可由本机归档校验恢复的历史 PDF，才可成为
迁出候选。原始 URL、公告时间、SHA-256 和解析版本始终保留在数据库中。

## 迁移协议

1. 在服务器生成候选清单：文件路径、大小、SHA-256、关联公司、报告期、
   队列状态和最近引用时间。
2. 下载到本机冷归档目录，按 SHA-256 和字节数逐文件校验，并生成不可覆盖
   的迁移回执。
3. 数据库记录本机归档定位及 `cold_archived` 状态；解析、再验证和增长研究
   队列必须排除非服务器驻留文件。
4. 对迁移回执抽样执行“本机文件 -> Hash -> 原始 URL/数据库记录”追溯检查。
5. 只有备份、校验、数据库状态更新和抽查均成功后，才由独立的显式清理命令
   删除服务器副本。默认命令只复制和校验，不删除。

## 运行边界

- 服务器磁盘保护阈值保持至少 2 GiB，低于阈值时停止下载和归档写入。
- 不将 WPS 云盘作为原始 PDF 的运行存储。
- 任何冷归档文件恢复到服务器时，必须重新校验 SHA-256，且恢复行为写入审计
  记录。
- 服务器找不到本地原件时，任务必须显示“冷归档待恢复”，不能把缺文件当作
  数据缺失、也不能用新下载的不同版本静默覆盖。
