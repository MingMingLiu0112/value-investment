- 至少形成一份具有真实来源、可复算、经独立经济研究复核的非压力主估值候选，并走现有合法准入流程。该必选项未完成时，不得称价值策略已闭环；不得自行创建审核身份或伪造签名。
- 研究结论可合理为 WAIT、拒绝或无法评价。没有低估公司是合法结果，但资料不足不能解释成市场没有机会。

立即复用已有五组经济审阅材料（EARNINGS / DISTRIBUTION / DURATION / COST_TERMINAL / EVENT_MODEL）：把独立复算的现金时序、终端占比、资本成本敏感性和反证接入当前研究读模型，数值沿用核验计算而非硬编码报告或让 LLM 计算。未来假设必须研究其合理区间、依据与可证伪性，不要求“未来已确定”才允许条件研究；条件研究也不能自行升格为 G3。不得再以实现签名运输/身份校验替代上述经济判断。既有原生研究 CLI 已完成，剩余消费者连接要说明具体断点。

每个影响结论的缺口应落实到所缺事实/判断、可行来源、下一动作和可证伪条件。不能长期只重复“待审核”；可公开调查和工程消除的缺口由代理完成，真正需要授权或主观投资选择的内容再集中交给用户。

## 6. 波段链：独立于价值主估值，独立承担验证要求

完成：真实行业/主题与活跃度观察 -> 候选变化 -> 已完成价格结构 -> 入场/失效条件 -> 原入场连续性 -> 加减退出解释 -> 策略独立验证 -> 共享组合风控。

- 继承既有版本化独立波段准入，不把价值 G3 当作波段候选的前置条件；数据、事件、可执行性、独立验证和组合约束仍不可绕过。
- 对既有日线/60分钟/15分钟规则逐条补足出处、经济假说及适用性验证。分钟数据不足不能从日线拼造，未完成 K 线不能冒充收盘确认。
- 历史候选池按当时成分/公告/规则生成，保留入池、离池及其原因；离开候选池不等于已有持仓必须卖出。
- 原始入场理由、保护阈值及已观察破位不能被后续反弹或滚动阈值覆盖。缺失覆盖不能推出 HOLD/ADD；公司行动不明确时拒绝假定价格可比。
- 区分参考 case、已确认真实 Entry、模拟 Entry、真实可卖数量。现有十个无 Entry 的案例不构成实盘持仓验证。
- 做费用、滑点、流动性、涨跌停、停牌、交易单位、T+1、可卖数量、公司行动、信号与成交时序的适用性验证；具体制度向交易所等官方来源核查，不能套统一百分比。
- 独立时序样本外/滚动验证，防未来函数、幸存者偏差、调参泄漏和多次试验选择偏差；报告基准、净收益/回撤/换手/暴露/交易数、分时期稳定性及不确定性。不得用三天回放证明长期有效，不能回填伪造前瞻 Shadow。
- 若历史可获得数据不足，明确哪些规则只能做结构回放，哪些具有真实 PIT/OOS 证据；继续完成不依赖缺失数据的业务连接。不得让结果永远停留在孤立 Markdown，主线要消费解释合同进入 Web。

## 7. 双策略仓位与人工成交闭环

复用现有账户、IPS、Entry Thesis、风险计算、成交与日记，不新建平行账本。已上线的一次性演练是保留回归基线，本阶段必须升级到真正可持续使用的隔离模拟账户。

## 8. 每日跟踪必须实际跑通

修复“只刷新行情、仍展示旧研究而不解释有效性”的产品断点。保留不可变研究基准，新增/复用明确的最近事件覆盖、最近研究复核、模型有效性、行情日期、决策生成和程序版本，不把系统时钟写成研究进展。

先处理当前真实业务断点：分市场采集覆盖及失败展示、假日/收盘日历、未审核事件导致的模型有效性、模拟账户状态的增量复核。允许保留有来源和日期的部分市场研究，但不得以部分覆盖冒充全市场完成；禁止通过浏览器绕过来源访问限制。

复用既有每日入口：数据采集与归档 -> 覆盖/变更检测 -> 重要性与依赖判断 -> 只重算受影响研究/估值/计划 -> 组合复核 -> 原子发布 -> Web提醒及可追溯回执。

- 无重大变化可以保留原研究基准日，但只有真实完成检查才能推进“复核覆盖至”；新财报、分红/回购、资本结构、重大公告、Thesis breaker 与价格区域变化要触发相应处理。
- 缺行情不能清空内在价值；缺公告不能写“没有公告”；审核未完成不能仍标当前有效。过期和不完整保留可读历史与具体原因，不显示为今日可操作。
- 验证无变化、重要变化、源冲突、过期、接口失败、重试、重复运行、部分成功与断点恢复；恢复不能重复记账或重复通知。
- 每日未运行、运行失败与运行后无变化必须不同；验证交易日历、时区、收盘完成状态，不只用工作日判断当前行情。
- 采用一份真实当前市场快照做手动端到端运行，并用冻结来源测试其前一时点/事件后的变化。历史时钟测试必须标明，不冒充已累计多日真实运行。

每轮从唯一台账与实际 diff 恢复，优先解决最接近用户业务结果的断点。只重新核对发生变化的代码、来源和验收；不重复读取完整历史，不为增加轮次重跑通过检查。每个包先写清用户路径、现有断点、输出和停止条件；交付记录同时区分已提交、已合入、已推送、CI、已在8001上线，不能混称“完成”。

有界研究：已调查的问题只有新证据能改变假设范围、经济判断、模型适用性或动作解释时才重开；否则记录不确定性和重开条件并推进消费者。不能把无法验证的未来预测改写成确定事实，也不能无限搜资料拖延已有条件研究的可用展示。不断完成可测试的纵向切片；不要每轮重新规划、只追加文档、只补防护测试后停止。阶段结果必须同时包含“用户现在能做什么”和“仍不能据此做什么”。

跨会话交接和外部等待不是停止整个 Goal 的理由。阶段收尾后继续依赖已满足的下一任务。必要人工问题集中、具体地提出一次：所需输入/授权、用途、影响和替代路线；普通查询、测试、公开资料研究及已授权本地集成不反复询问。

最终交付：当前commit与干净状态；两策略规格及验证报告；三类状态明确的真实/模拟/待准入案例；8001用户路径与流程图；买入、加仓、持有、减仓、退出理由及原始Thesis对照；组合和每日更新验收；测试及CI实际结果；用户待确认项目、失败策略和尚未完成的实盘条件。不得承诺收益或把“辅助复核”表述为必须遵从的交易指令。
