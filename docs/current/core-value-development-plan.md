## 开发顺序

1. **P0：D2→E2通用经营现金编译。** 沿现有调用链定位证券绑定、预置年度路径和错误通用化的特殊合同；先完成类型适用判断、年度驱动与现金政策输入。复用已有真实响应和事实，仅在输入改变且确有必要时运行有预算的模型调用。产物必须被E2实际消费，不能只新增草案Schema。
2. **P0：E2→F1→F2条件研究出口。** 同一入口生成年度账并进入既有估值与价格政策。A并行补其具体缺失字段，C复用既有适用边界。形成有依据的条件区间与价格草案，或者明确的经济拒绝；拒绝样本不能代替整个模块的成功路径验收。
3. **P1：B→D链及E1持续跟踪。** 前两步证明通用迁移后，接预算内候选自动研究与增量更新；实现单家隔离、重试、来源刷新和变化解释，不扩大行业模型或全市场Agent并发。
4. **随包完成G1/G2，而非最后补界面。** 每包将实际产物、精确缺口、历史版本接入既有API/页面/任务服务。用真实输入做独立模块及直接下游验证，再运行必要Core/Web检查；按授权更新唯一8001并验证实际操作。
